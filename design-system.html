Armadilha do legado — var(--ease-out) sem definição

Os CSS das LPs usam var(--ease-out) em várias transições (WA FAB, hovers), mas nenhuma LP define o token. Resultado: a declaração inteira é invalidada e a transição é descartada em silêncio.

  • Em página nova: sempre declare --ease-out: cubic-bezier(0.22, 1, 0.36, 1) no :root antes de copiar qualquer bloco de LP.
  • Ao reutilizar CSS de LP: confira com o DevTools se a transição realmente roda — se o token faltar, o hover “funciona” mas sem animação.

Badges — regra obrigatória

Nunca use badges

Regra de ouro: não use badges, chips de confiança, selos em pílula nem fileiras de ícone+rótulo do tipo “LGPD · Dados criptografados · Feito para o direito brasileiro”.

Esse padrão é o clichê visual de landing page gerada por IA: empilha credibilidade genérica, empobrece a hierarquia e deixa o produto com cara de template.

  • Proibido em páginas novas e revisões: .chip, .hero-chips, .trust-pill / marquee de selos no hero, badges de “segurança”, “IA”, “LGPD”, “criptografado”, “100% brasileiro”, contadores-selo e qualquer fileira de pílulas decorativas sob o título.
  • Não contorna a regra trocando só o texto do badge ou o ícone — o formato em si é o problema.
  • Permitido (não são badges): .sol-tag / eyebrows de seção, .feat-num, .win-live, .modal-eyebrow, labels de formulário, .hero-tag só como sugestões dentro do mock de produto (não como selo de marketing).
  • Como transmitir confiança sem badge: copy concreta no lede, prova social real (depoimento, número, caso), footer legal discreto, formulário + WhatsApp, e o próprio mock do produto.

06 · Movimento & leitura estável

Sutil, rápido — sem atrapalhar quem lê.

Todo movimento usa --ease-out. Prioridade #1: a página não pode piscar, subir ou descer sozinha enquanto o usuário lê. Micro-loops só em elementos minúsculos; hovers reagem com brilho/borda, não com lift vertical no layout de leitura.

Regra obrigatória — leitura estável

A home e as LPs devem se comportar como um documento estável: o scroll é do usuário, não do JS/CSS. Violação típica: texto “pulando” enquanto se lê o meio da página.

RegraFazerNão fazer
Scroll do documento html { scroll-behavior: auto; } scroll-behavior: smooth (global)
Reveal / entrada de seção .reveal { opacity: 1; transform: none; } + class visible no load opacity:0 + translateY(20–24px) no scroll
Stagger em grids filhos sempre legíveis (sem cascata vertical) delays 0.05–0.45s com translateY por card
Hover de cards / botões border, box-shadow, filter:brightness, ícone scale translateY(-1…-4px) em .btn / .sol-card / .feat-card
Marquee (trust / ganhos) animação CSS + pause hover + .is-offscreen · contain:layout paint · overflow-anchor:none requestAnimationFrame lendo scrollWidth todo frame
Chat do hero conversa estática (render 1×) · altura fixa .win-body loop infinito, typing, createIcons no documento inteiro
Ícones Lucide [data-lucide]{display:inline-block} + width/height no markup · createIcons({ root }) createIcons() global em loops / a cada mensagem
content-visibility evitar em seções de marketing longas content-visibility:auto em blocks que o usuário rola lendo

Divergência legada — lift vertical nos CSS das LPs

Os arquivos das LPs ainda contêm hovers com translateY (ex.: .btn.primary:hover{transform:translateY(-1px)} e .who-card:hover{translateY(-3px)} no DET). Isso viola a regra de leitura estável e não foi corrigido lá porque as páginas no ar não devem ser alteradas por este guia.

  • Em página nova: ao copiar qualquer bloco de CSS de LP, remova os transforms de hover — hover só com borda, sombra, brightness e ícone (scale/rotate no ícone é ok).
  • Referência correta: os hovers da Camada 1 deste guia (home) já estão sem lift — copie daqui, não da LP.

09 · Voz & copy

Como escrever para parecer Juris8.

Design profissional sem copy certa vira template. Tom: advogado falando com advogado — direto, concreto, sem hype vazio e sem cara de IA genérica.

Fazer

  • Benefício no título, mecanismo no lede
  • Verbos de resultado: pré-elabora, monitora, qualifica, minuta
  • Prova concreta: “14 páginas”, “antes da consulta”, “antes do prazo”
  • CTAs de isca: “Quero minha demonstração”, “Faça seu teste”
  • Uma ideia por card; trecho em .grad no fim do H2/H3

Não fazer

  • “Revolucione”, “o futuro da advocacia”, “100% IA”
  • CTAs literais: “Ir para o formulário”, “Clique aqui”
  • Badges LGPD / criptografado no hero (ver #sem-badges)
  • Parágrafos longos (> 3 linhas) em card

Só publica quando a nota for 10.

Use este checklist em toda página nova ou revisão. Se algum item falhar, a página não está pronta — independente de “parecer bonita”.

Fundação visual

  • Tokens :root do perfil completo (home + LP, sem hex solto)
  • --ease-out declarado (armadilha do legado LP)
  • Geist + Mono + Serif (se display) via Google Fonts
  • Ambient orbs + hairlines escuros
  • .shell max 1400 · pad clamp
  • Section padding clamp(40–72) · mobile clamp(32–52)
  • Hero padding clamp(48–80 / 36–56)

Componentes & chrome

  • Navbar sticky + burger ≤640 + scrolled shadow
  • Footer 4 colunas + WA/Instagram corretos
  • WA FAB com dismiss localStorage
  • Botões primary/secondary (1 primary por bloco)
  • Fecha com .cta-final real (nunca .cta-panel)
  • Form com labels, consent e source Supabase único
  • Lucide com width/height + createIcons

Leitura estável #leitura-estavel

  • scroll-behavior: auto
  • Reveal sem opacity:0 / translateY
  • Hover sem lift vertical em cards/botões
  • Sem translateY herdado de CSS de LP
  • Marquee só CSS + pause offscreen
  • Chat hero estático (sem loop)
  • Sem content-visibility em blocos de leitura

Conteúdo & QA

  • Zero badges/chips de confiança no hero
  • Copy com fórmulas de #voz
  • CTAs isca (não “formulário”)
  • Trust strip fora do hero · copy de capacidade (não selo genérico)
  • Mobile: hero center ≤980 · CTAs 52px ≤640 · inputs 16px
  • data-screen-label em toda section
  • Meta title/description + og:image
  • Links internos / âncoras / LPs sem 404

Critério de nota 10
